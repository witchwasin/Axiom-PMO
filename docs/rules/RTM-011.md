# RTM-011 - Anti-forged verified status in RTM

| | |
|---|---|
| Level | FAIL |
| Gate | Release |
| Applies to | Strict |
| Artifacts | `RTM.json`, `RELEASE.md` |

## What this rule checks

In `RTM.json`:
When any traceability row claims `status: verified`, the corresponding test referenced in `test_ref` must have an actual `Result: passed` row in `RELEASE.md` under `## Test Summary`.

## Why it blocks

Claiming `status: verified` before code has been written and tested is an anti-pattern. An RTM row remains `supported` throughout discovery, design, and handoff, and only transitions to `verified` once tests pass with verified execution evidence.

## How to fix

Keep the row's `status` as `supported` in `RTM.json` until test execution in `RELEASE.md` `## Test Summary` is completed and passed.
