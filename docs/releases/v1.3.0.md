# Axiom-PMO 1.3.0 — Release Notes

The Claude Code integration, and execution-evidence hardening. Milestone 6
ships Axiom-PMO as an optional Claude Code plugin; Milestone 5.5 closes a
provenance gap in `ci-check` evidence found after Milestone 5 was already
accepted and closed.

Backward compatible. Every existing local invocation and the GitHub Action
are unchanged. The plugin and its advisory hook are both opt-in; the hook is
off by default.

## Claude Code integration (Milestone 6)

*Optional. Milestones 1–5 remain the product; nothing in them requires this.*

Axiom-PMO installs as a Claude Code plugin, outside the user's repository.
One fenced, namespaced block is appended to the repository's `AGENTS.md` —
that file has to be a real file because Codex and Cursor read it too, and a
Claude-only plugin would not reach them.

```bash
git clone https://github.com/witchwasin/Axiom-PMO   # next to your project, not inside it
claude plugin marketplace add ./Axiom-PMO
claude plugin install axiom-pmo@axiom-pmo
```

Then, from inside your own project (clone at `../Axiom-PMO`):

```bash
node ../Axiom-PMO/cli/axiom.mjs setup claude --project . --dry-run
```

Full walkthrough with every command path made explicit:
[`docs/guides/claude-code-integration.md`](../guides/claude-code-integration.md).

What it does not do, stated because it is the easiest thing to
misrepresent:

> Claude Code receives the approved scope and authority as governed context.
> Axiom-PMO verifies afterwards whether the implementation remained within
> them. Nothing in Milestone 6 prevents an out-of-scope edit.

Detection stays where it always was: SCOPE-DIFF and the `EXEC-*` rules,
after execution. No authority, evidence, or approval logic moved out of
Milestones 1–5.

An optional, opt-in, report-only advisory hook can flag an out-of-scope edit
as it happens — it emits a note, never a permission decision, and cannot
block an edit at any input.

See [`docs/guides/claude-code-integration.md`](../guides/claude-code-integration.md)
and the [15-minute walkthrough](../guides/claude-code-walkthrough.md).

Independently reviewed across three rounds (2 FATAL, 8 MAJOR, 2 MINOR, all
resolved), final verdict ACCEPT WITH MINOR REVISIONS. Human Owner tested,
accepted, and closed. Full history in
[`docs/reviews/m6-reviewer-index.md`](../reviews/m6-reviewer-index.md) and
[`docs/architecture/m6-threat-model.md`](../architecture/m6-threat-model.md).

**Known limitations, carried into this release rather than hidden:**

- A git-source plugin install carries the whole repository (~10 MB, mostly
  `tests/`); only the plugin's runtime components are loaded. Accepted as a
  non-blocking `v1.3.0` limitation (`DEC-008`) — scoped to this release, not
  a rejection of ever shrinking it.
- Plugin update/version-drift: **narrowed, not closed.** The plugin's
  declared version is confirmed to be Claude Code's own update/cache
  identity (real install evidence, not assumed). Two specific gaps —
  whether an update replaces an already-loaded plugin mid-session, and
  whether a GitHub-hosted marketplace source behaves like the
  local-directory source tested — remain unexercised and are accepted as
  bounded, non-blocking `v1.3.0` limitations (`DEC-009`).
- Cross-plugin hook ordering: **closed**, to the level Claude Code's own
  platform contract makes provable (hooks run in parallel with no
  guaranteed order by design; verified independently registered and
  order-independent by both a real coexistence install and deterministic
  tests).

Full evidence for all three: `ROADMAP.md`'s deferred technical debt table and
`docs/architecture/m6-threat-model.md`.

## `ci-check` provenance hardening (Milestone 5.5)

A check that failed once and was later re-run to green could never verify as
`ci-check` evidence — the adapter searched by check-run **name**, and the
API keeps listing a run's failed history forever under that name.
`Test-CiCheckEvidence` now accepts an optional `check_run_id` that binds to
one exact run instead, closing that permanent false negative. Check-name
comparison is also now case-sensitive throughout, closing a separate
same-name-different-case gap found in review.

Backward compatible: an entry with only `name`/`commit_sha` takes the
unchanged search path.

## Upgrading from 1.2

No migration required. The plugin is entirely opt-in; declining it changes
nothing about how Milestones 1–5 behave.
