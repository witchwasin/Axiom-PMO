# 10_why_handoff

**[เปิดเรื่อง]**
มาเจาะลึกกันเรื่องด่าน Handoff ครับ ทำไมถึงต้องมีด่านนี้แยกออกมาต่างหาก? ทั้งๆ ที่เอกสารครบทุกช่องแล้วก็น่าจะส่งให้ Dev ทำต่อได้เลยนี่นา

**[ขยายความ]**
**[สำหรับผู้บริหาร]**: บางครั้งการที่ทีมงานกรอกแบบฟอร์มครบทุกช่อง ไม่ได้แปลว่างานนั้นจะลงมือทำได้จริงนะครับ เรามักจะพบว่า พอส่งงานให้ Dev ไปแล้ว Dev กลับต้องเสียเวลาไปกับการแก้ปัญหาพื้นฐาน เช่น รันโค้ดไม่ขึ้น หรือระบบไม่รองรับ ซึ่งปัญหาแต่ละเคส ทำให้เราเสียเวลาทำงานของทีมไปเป็นวันๆ เลยครับ
**[สำหรับทีมเทคนิค]**: ลองดู 5 เคสตัวอย่างนี้ครับ เช่น การเรียงลำดับ Build ผิด เอา Schema กลางไปไว้หลังสุด วิศวกรสองคนก็นั่งงมไปทั้งวัน หรือทำฟีเจอร์กล้อง แต่ไม่มีการคุยเรื่อง Environment ว่าจะ Serve แบบ HTTPS ยังไง พอมารันบนแท็บเล็ตก็พัง 

ปัญหาก็คือ กฎทั่วๆ ไปที่เช็คแค่ว่า "ช่องนี้กรอกข้อมูลหรือยัง" จะมองไม่เห็นความพัง 5 แบบนี้เลยครับ มันเลยเป็นเหตุผลที่เราต้องมีด่าน Handoff ที่ฉลาดกว่านั้น

**[คำถามที่อาจพบ & สำหรับสายเทคนิค]**
กฎของ Axiom-PMO ในด่านนี้จึงไม่ได้แค่ตรวจ Syntax แต่ตรวจ Dependency Tree ว่าเรียงลำดับถูกไหม มี Seed data จริงๆ ให้เทสต์ครอบคลุมหรือเปล่า ซึ่งถ้าปล่อยผ่านไป มันจะไปบรรลัยในเช้าวันจันทร์ตอนเริ่ม Sprint แน่นอน

**[ส่งเข้าหน้าถัดไป]**
แล้ว Validator ของด่าน Handoff มันทำงานยังไงให้ฉลาดขึ้นโดยที่ไม่มั่ว? เราใช้เทคนิคการแบ่งการตรวจสอบออกเป็น 2 ชั้นครับ
