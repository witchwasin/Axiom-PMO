# SRS-001 - Software Requirements Specification section presence and status

| | |
|---|---|
| Level | FAIL |
| Gate | Design, Handoff, Release |
| Applies to | Standard, Strict (when `Spec depth: full`) |
| Artifacts | `DESIGN/SRS.md` |

## What this rule checks

1. `DESIGN/SRS.md` exists when required by mode under `Spec depth: full`.
2. Every section configured in `pmo-config/depth-policy.json` `srs_sections` for the project's mode is present.
3. Every section declares a valid `Status: specified` or `Status: not_required` line.
4. When `Status: not_required` is used, the policy must allow waiving that section, and a `Rationale:` of at least 4 words must be supplied.
5. When `Status: specified` is used, the section must not be empty.

## Why it blocks

Under full specification depth, complex systems need structured requirements analysis detailing actors, interfaces, constraints, and compliance. Blank or missing sections indicate incomplete discovery.

## What the validator deliberately does not decide

The validator does not judge the semantic quality of the requirements description.

## How to fix

Create `DESIGN/SRS.md` from `templates/SRS.md` and complete all sections required for your governance mode.
