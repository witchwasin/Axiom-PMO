# Axiom-PMO 2.1.0 — Release Notes

2.1 finishes three optional governed tracks that 2.0 left as contracts on
paper, and changes what CI costs to run. Nothing here is required: each track
activates by the existence of its artifacts, so a project that declares none of
them validates exactly as it did on 2.0.0.

Backward compatible for projects. The one removal affects this repository's own
development records, not the product — see [Removed](#removed) below.

## Externalization gate

`EXTERNALIZATION.json` records every transfer that leaves the governed
boundary: what went out, to which provider, for what purpose, and whether a
network transfer actually occurred.

- Classifications (`Public`, `Internal`, `Confidential`, `Restricted`) are
  policy-owned in `pmo-config/orchestration-policy.json`, not hardcoded.
- `network_transfer_occurred` is a required JSON boolean. A transfer that
  omits it no longer passes, because "we did not send anything" is a claim that
  has to be made explicitly to be auditable.
- A declared clean scan must agree with a deterministic re-scan; sensitive
  paths come from `policy.permissions.sensitive_paths` and match nested files,
  not just basenames.
- `Confidential` and `Restricted` require named Human evidence. `Public` may
  proceed under policy. The `Internal` default is a Human Owner setting
  (`externalization.internal_default_human_review`), not an AI decision.

See [`docs/concepts/externalization.md`](../concepts/externalization.md).

## Claude Design provider workflow

An optional governed handoff for UI work: a digest-bound input manifest goes
out, output comes back under `DESIGN/CLAUDE-DESIGN/OUTPUT/**`, and a named
Human accepts it.

- The preflight now compares `preflight.manifest_digest` against the current
  input manifest, so acceptance recorded against a stale input fails.
- Output must be declared in an inventory, be non-empty, and live inside
  `OUTPUT/**`. An empty output set with the empty-set digest no longer passes.
- Finding routing is derived from impact, not self-asserted: an open technical
  finding cannot coexist with accepted output.
- At Handoff and Release the review must exist. Previously an absent
  `REVIEW.json` reported PASS.

See [`docs/concepts/claude-design-workflow.md`](../concepts/claude-design-workflow.md).

## Guided research

`RESEARCH.md` plus a provenance registry, before Scope approval.

- Every material claim resolves to a real source. Pattern-shaped references
  (`MOM-…`, `REQ-…`, `DEC-…`) are checked against the project's Source Snapshot
  and artifacts rather than accepted because they look like references.
- Impact Assessment rows are parsed. An accepted product impact needs a
  governed proposal, a named Human owner, and a resolvable `DEC-###` — and so
  does a rejected one, because rejection is also a decision.
- A `stopped` state with a reason and a next action lets an unavailable
  provider be reported truthfully. A stopped track stays actionable; it is
  never presented as completed research.
- Provenance carries a deterministic freshness contract — UTC ISO-8601
  `retrieved_at`, source dates when a cutoff is active — without pretending
  local validation can verify a web source's truth.

See [`docs/concepts/research-workflow.md`](../concepts/research-workflow.md).

## Canonical artifact hashing

One shared helper normalizes governed text before hashing: decode UTF-8, strip
only the BOM, normalize `CRLF`/`CR` to `LF`, hash those bytes. Binary
extensions hash as original bytes, and an unknown extension fails safe to byte
hashing.

Before this, checking out the repository with `core.autocrlf=true` changed
every provider and externalization digest and made current evidence read as
stale. Evidence that depends on a checkout setting is not evidence.

## Risk-based CI

`.github/workflows/pmo-checks.yml` no longer runs every suite on every host on
every change. A `determine-profile` job resolves one of three profiles:

| Profile | When | Scope |
|---|---|---|
| `fast` | docs, reports, ordinary work | five checks on one Linux `pwsh` host |
| `targeted` | code in a known area | full local-equivalent suite on the relevant host(s) |
| `full` | merge/release gate, high-risk change | every required host + the dogfood jobs |

`full` is unchanged from 2.0 — only how often it is selected automatically
changed. The path-to-profile mapping lives in `scripts/ci-profile.ps1` and is
guarded by `tests/helpers/ci-profile-tests.ps1`; unknown paths escalate one
level rather than falling back to cheap.

**If you require status checks on this repository, require
`determine-profile`.** GitHub reports a skipped job as success, so a host job
gated on a profile is not evidence that a pull request ran on that host. See
[`docs/architecture/ci-risk-based.md`](../architecture/ci-risk-based.md).

## Also changed

- Physical path containment is shared across the new validators. A symlink or
  Windows junction can no longer resolve outside a project boundary.
- `scripts/pmo-status.ps1` derives lifecycle and freshness from validation
  diagnostics instead of file existence, counts every non-terminal governed
  change, and names the next Human or automated action in both Text and JSON.

## Removed

This repository's own development records — internal planning, review, and
report directories, and the framework-level `decision-log.md` — are no longer
published. They documented how this repository was built, not how to use it.

`DOCTOR-012`, which checked decision-id uniqueness in that framework-level log,
was removed with it. The same property inside a *project* is still enforced by
the `EXEC` and `HANDOFF` rules that resolve a `DEC-###` at validation time, and
`templates/decision-log.md` is unchanged.

## Upgrading

No action required. If you want a track, add its artifacts:

| Track | Activate by creating |
|---|---|
| Externalization | `EXTERNALIZATION.json` |
| Guided research | `RESEARCH/RESEARCH.md` + `RESEARCH/PROVENANCE.json` |
| Claude Design | `DESIGN/CLAUDE-DESIGN/INPUT-MANIFEST.json` |

If you already used the provider or externalization tracks from a pre-release
build, regenerate their digests once with `scripts/design-provider-digest.ps1`
so they use the canonical hash.
