# SRS-003 - Non-Functional Requirements traceability and evidence

| | |
|---|---|
| Level | FAIL |
| Gate | Design, Handoff, Release |
| Applies to | Standard, Strict (when `Spec depth: full`) |
| Artifacts | `DESIGN/SRS.md` |

## What this rule checks

In `DESIGN/SRS.md` under `### Non-Functional Requirements`:
1. Every row has a `Source Ref` matching the configured source reference pattern (e.g. `MOM-YYYYMMDD item-N`).
2. Every row has an `Evidence Status` from `pmo-config/policy.json` `enums.evidence_statuses`.

## Why it blocks

Unanchored NFRs risk hallucinating operational requirements not agreed with stakeholders.

## How to fix

Ensure every NFR row points to an authenticated source meeting or document reference and declares its evidence status.
