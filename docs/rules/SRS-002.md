# SRS-002 - Non-Functional Requirements measurement completeness

| | |
|---|---|
| Level | FAIL |
| Gate | Design, Handoff, Release |
| Applies to | Standard, Strict (when `Spec depth: full`) |
| Artifacts | `DESIGN/SRS.md` |

## What this rule checks

In `DESIGN/SRS.md` under `### Non-Functional Requirements`:
1. Every NFR row has an `ID`, `Category`, `Target`, and `Measurement Method`.
2. No target or measurement method is left as a `<placeholder>` or blank.

## Why it blocks

An NFR without a measurable target (e.g. "system must be fast") is unverifiable and untestable. Engineering handoff requires unambiguous criteria.

## How to fix

Specify explicit target thresholds and verifiable measurement methods:

```markdown
| ID | Category | Target | Measurement Method | Source Ref | Evidence Status |
|---|---|---|---|---|---|
| NFR-001 | performance | p95 latency < 200ms at 500 RPS | k6 load test suite | MOM-20260710 item-2 | supported |
```
