# API-001 - OpenAPI specification presence and version header

| | |
|---|---|
| Level | FAIL |
| Gate | Design, Handoff, Release |
| Applies to | Standard, Strict (when `Spec depth: full` and API contract is present) |
| Artifacts | `DESIGN/API/openapi.yaml` |

## What this rule checks

When `DESIGN/API/openapi.yaml` is present:
1. It must declare a valid `openapi: 3.x.x` version header (e.g. `3.0.3` or `3.1.0`).

## Why it blocks

Invalid or unversioned API contract files prevent downstream SDK generation and contract test tooling from running.

## How to fix

Ensure `DESIGN/API/openapi.yaml` starts with a standard OpenAPI version declaration:

```yaml
openapi: 3.0.3
info:
  title: Service API
  version: 1.0.0
```
