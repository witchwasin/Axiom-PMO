# Axiom-PMO 2.2.0 — Release Notes

The PowerShell-to-Node/TypeScript interpreter migration (Phases 0–10) is
complete. The Node engine — ported from the PowerShell
reference, differentially proven byte-identical, canary-verified on real
Windows/Linux/macOS hosts — is now the CLI's only execution path, and the
PowerShell reference it was proven against has been deleted entirely.

**No governance behavior changes.** Every command produces the exact stdout,
stderr, and exit code it always has. This release ships what the differential
proof already established, not new logic. **Not a breaking change for
consumers:** inputs, outputs, and exit-code semantics are unchanged from
2.1.0.

## Node engine is now the only execution path

- `cli/axiom.mjs`: the in-process TypeScript engine is unconditional. No
  environment variable selects an alternate path anymore, and the
  `AXIOM_ROLLBACK_PWSH` toggle introduced during the canary window is
  removed.
- `action.yml` no longer describes PowerShell as the execution engine.
- All consumer-facing documentation (`README.md`, `TESTING.md`,
  `CONTRIBUTING.md`, install/runtime guides, architecture and rule docs,
  skill definitions) is reconciled to describe the Node engine. Historical
  records — this changelog, past release notes, and
  [`docs/architecture/powershell-portability.md`](../architecture/powershell-portability.md)
  (the pitfalls document) — are left intact under a reviewed allowlist.

## What was removed

`scripts/*.ps1` (60 files), `tests/helpers/*.ps1` and `tests/e2e/*.ps1` (29
files), `src/probe/marker-harness.ps1`, and `src/probe/pwsh-resolver.ts` — the
entire PowerShell reference implementation and its adapter code, 92 files
total. `docs/guides/powershell-runtime.md`, the PowerShell 7 install guide, is
retired along with the runtime it documented.

Every differential probe that used to compare live against the PowerShell
reference now runs as a golden-fixture regression instead, captured from the
reference before deletion by capture scripts that briefly lived under
`Fixed_plan/phase0/` (see [Fixed_plan/ retired](#fixed_plan-retired) below) —
the golden fixtures they produced live on under `tests/golden/`.

## Proof, not assertion

The claim "behavior is unchanged" is backed by a final-tree differential gate
run at each of the cutover and deletion commits, comparing diagnostics,
exits, stdout/stderr, generated files, and hashes between the frozen
PowerShell reference and the Node candidate across the full compatibility-case
manifest — archived, at the time, in the migration's own phase reports (see
[Fixed_plan/ retired](#fixed_plan-retired) below). Ten real bugs were found and
fixed against the live reference during the migration, each reproduced before
being fixed rather than reasoned about — among them six hardcoded `"/"`
path-separator bugs invisible on every non-Windows host, caught only by a real
Windows CI run, and a canonical-normalizer divergence from the reference's own
backslash-pair fold.

## CI/CD workflow rewrite

`.github/workflows/pmo-checks.yml` no longer invokes `pwsh` or any `.ps1`
script anywhere — `determine-profile`, `fast-checks`, `targeted-checks`, the
three full-profile host jobs, and `dogfood-ci-check-evidence` all now run
through Node CLIs (`ci-profile-cli.ts`, `run-ci-suite-cli.ts`). The full-profile
job ids were later renamed off their historical `-pwsh7` suffix
(`pmo-checks-windows` / `-linux` / `-macos`) once confirmed no branch
protection rule pinned the old names.

## Governance decisions behind this release

All approved by the Human Owner: pre-authorizing Phases 8–10 in principle
(`DEC-027`); resizing the Phase 7 canary settling window from 30 to 10 and
finally waiving it at N=1 (`DEC-028`–`DEC-030`); the named-Human CR-017
supply-chain and containment sign-off before cutover (`DEC-031`); waiving
Phase 9's "separate Human reviewer" requirement for this solo-maintainer
project (`DEC-032`); proceeding to deletion immediately after cutover
(`DEC-033`); and approving the mid-Phase-9 CI/CD workflow rewrite once it was
discovered to be necessary (`DEC-034`). These were recorded, at the time, in
the migration's own decision log (see below).

## Upgrading

No action required. Inputs, outputs, and exit codes are unchanged from 2.1.0.
If your CI or branch protection referenced the full-profile job ids by their
old `-pwsh7` names, update to `pmo-checks-windows` / `pmo-checks-linux` /
`pmo-checks-macos`.

## `Fixed_plan/` retired

`Fixed_plan/` — the master plan, decision log, AI-review transcripts, and
per-phase reports that documented how this migration was planned and
executed — was itself removed from the published repository on 2026-08-18,
once the migration it tracked had closed. It documented how the migration was
built, not how to use the product, on the same basis as the framework-level
`decision-log.md` removed at `2.1.0` (see `CHANGELOG.md`). The two pieces of
its state that CI still depends on at runtime — the canary baseline/log and
the compatibility-case manifest — moved to `.ci/canary/` rather than being
deleted; see `scripts/canary-baseline.mjs`.
